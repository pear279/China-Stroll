# MVP 首条功能开发记录

## 当前结果

2026 年 8 月 27 日完成第一条可运行过程。范围限制在一条北京旅行和故宫、景山、天坛三个样本地点。

用户现在可以完成以下操作。

1. 在测试模式输入邮箱后进入临时账号，或打开本地预览。邮箱不发送、不验证，只在当前标签页保存遮罩显示文字。
2. 创建旅行并填写可选日期。
3. 把三个样本地点逐个加入第一天。
4. 在列表和地图之间切换同一个地点。
5. 查看行程调整建议和风险提示。
6. 确认后更新访问时间，旅行版本增加一次。
7. 刷新页面后恢复本地预览。

三张定制印章图已经作为地点卡片图片使用。

## 2026 年 8 月 29 日功能扩展

景点展示图已扩到 52 张，并统一生成 960 像素网页版本。地点卡片和详情抽屉使用同一张最新图片。PWA 只缓存用户打开过的景点图，避免首次访问下载全部资源。

景点详情增加收藏、加入指定日期、简介、看点、游览建议、拍照提示、可信导览和单景点问答。问答接口只读取已发布导览和已审核来源，模型不可用时使用导览摘录。预览模式不开放问答，页面会说明登录要求。

行程支持增加日期，用户可以把景点加入第二天及以后日期。新增服务端命令继续检查成员权限、旅行版本和命令标识，并写入改动记录。

地图改用项目内的 mapcn 源码，保留 `TravelMap` 业务包装。页面可以显示行程地点、附近景点和用户一次性位置。地图和列表通过地点编号互相选中，附近筛选支持一公里、三公里和五公里。

景点详情提供 Apple Maps、Google Maps 和高德搜索入口。高德暂时按名称搜索，等本地地图坐标转换适配完成后再传坐标。

本轮通过类型检查、代码检查、51 项自动化测试和网页生产构建。桌面浏览器与 390 像素宽度完成多日期、指定日期加入、收藏、详情抽屉和导航入口验收，控制台没有错误或警告。新增日期的 SQL 回滚测试已经补入仓库。Supabase 命令行工具可用，本机缺少 Docker 或 Podman，数据库测试无法启动，本轮没有应用线上迁移。

## 2026 年 8 月 30 日本地数据库验证

本机使用 OrbStack Docker Server 28.5.2 和 Supabase CLI 2.116.0 建立了本地 PostgreSQL 17 环境。`npm run db:verify` 从空库应用全部迁移和当前仅含内容审核说明的 `supabase/seed.sql`，执行两套 SQL 回滚测试，检查固定测试用户、临时地点和测试旅行没有残留，再从空库重建一次数据库。

`mvp_business_schema.sql` 和 `mvp_trip_commands.sql` 均通过。命令测试现在在自己的事务中创建已发布且完成坐标审核的 `forbidden-city` 夹具，不再依赖远程项目已有地点。两次迁移重建、权限、RLS、幂等、版本冲突、地点审核门槛和新增日期断言全部通过。本次没有运行 `supabase link` 或 `supabase db push`，新增迁移仍未应用到线上。

## 实现范围

前端使用 React、TypeScript、Vite、Tailwind CSS 和 PWA。地图组件由产品自己的 `TravelMap` 包装 MapLibre GL JS，页面只传入地点和选中状态。MapLibre Worker 随 Vite 构建，不依赖外部 Worker 地址。

Cloudflare Pages Functions 提供创建旅行、读取旅行、加入地点、生成建议和确认建议五类接口，并复用原有 Hono Worker 应用。页面与接口共用 `china-stroll.pages.dev`。每次写入先验证 Supabase 用户，再检查成员身份、旅行版本和命令标识。

Supabase 新增三个服务端命令函数。浏览器角色没有执行权限，只有 `service_role` 可以调用。创建旅行会同时创建第一天和改动记录。重复命令返回第一次结果，旧版本写入会失败。

行程建议已经支持在配置硅基流动密钥后调用 `deepseek-ai/DeepSeek-V4-Flash` 生成结构化草案。缺少密钥、请求失败或结果未通过校验时，服务端回到固定规则建议。确认写入规则保持不变。

## 验证结果

1. TypeScript 前端、Worker 和 Pages Functions 类型检查通过。
2. 二十个领域、接口、登录、旧行程坐标刷新与部署适配测试通过，覆盖输入限制、数据库结果校验、建议结构校验、同域接口选择和匿名登录分支。
3. Pages Functions 本地健康接口返回 200，未登录写入返回 401，旅行接口带 `private, no-store` 响应头。
4. 数据库命令测试先在回滚事务中通过，再应用到 Supabase，线上回滚测试再次通过。
5. 重复命令、旧版本冲突、建议确认和单次版本增加均已覆盖。
6. 桌面浏览器完成创建、加入三地、生成建议和确认建议。
7. 390 像素宽度没有水平溢出，刷新后预览可以恢复。
8. 浏览器检查没有错误或警告。
9. Supabase 安全检查没有发现问题，测试后四张业务写入表均为零记录。
10. 故宫、景山和天坛的地图标记完成坐标复核。三处展示点改为 OSM 底图对应的 WGS84 景区中心，数据库保存坐标系、复核时间和 OSM 对象编号。前端测试会检查每个样本是否有审核记录，地图图标使用底部尖端定位。浏览器里已有的预览行程会在打开时刷新三个样本坐标，不改变行程版本。
11. 2026 年 8 月 28 日发布提交 `3973fde`。线上临时账号完成创建旅行、加入三地、生成建议和确认建议，旅行版本从 1 增加到 5。故宫、景山和天坛的线上地图落点均在对应景区范围内。
12. 测试结束后清理临时旅行和匿名用户。清理测试发现拥有者成员保护规则阻止行程级联删除，修复后先在回滚事务验证单独删除仍被拒绝、整条行程可以删除，再应用到 Supabase。数据库最终恢复为零匿名用户。
