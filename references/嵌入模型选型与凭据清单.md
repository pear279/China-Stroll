# 嵌入模型选型与所需凭据

## 文档信息

版本 1.0，创建于 2026 年 8 月 28 日，对应《开发规划》任务 C4。

本文记录嵌入模型选型的核查结果、推荐方案和需要大小姐提供的凭据清单。

## 一　核查结论

DeepSeek 官方 API 目前只提供对话类模型，没有嵌入接口。

2026 年 8 月 28 日查阅 DeepSeek 官方文档的模型与价格页，全部可用模型是三个，`deepseek-v4-flash`、`deepseek-v4-pro`、`deepseek-v4-flash-vision-exp`。三者都是对话模型，功能列表覆盖 Json Output、Tool Calls、Responses API、Anthropic API、对话前缀续写、FIM 补全，没有 embeddings 端点。

搜索结果里出现的 `deepseek-embedding`、`deepseek-embedding-v1`、`text-embedding-3` 这类名字，来自第三方博客和聚合站点，官方文档里查不到。用这些模型名调用会直接返回模型不存在。

所以 DeepSeek V4 Flash 不能承担 C4 的向量生成任务。它能承担的是另一件事，见第三节。

## 二　推荐方案

把原来的一个角色拆成两个。

| 角色 | 用途 | 选定服务 |
| --- | --- | --- |
| 嵌入模型 | 把 165 条检索文档转成向量，把用户提问转成向量 | 硅基流动 BAAI/bge-m3 |
| 对话模型 | 拿到检索出的段落后生成导览回答 | DeepSeek V4 Flash |

这样拆的理由是，嵌入和对话是两类不同的能力，本来就不必来自同一家。大小姐指定 DeepSeek V4 Flash 的意图是控制成本并且用国内直连服务，这个意图在拆分后完整保留，因为 bge-m3 同样是国内直连且免费。

### 2.1 为什么选 bge-m3

四个理由。

第一，多语言是硬需求。产品要同时检索中文和英文内容，《景点数据与 AI 检索方案》第 91 行明确要求中英文使用同一个多语言向量模型，避免不同向量混用。bge-m3 支持 100 种以上语言，在 MIRACL 和 MKQA 这两个多语言与跨语言检索基准上表现靠前。

第二，中国大陆直连。接口地址是 `https://api.siliconflow.cn/v1/embeddings`，不需要代理。这一点对后面在北京做真机网络测试很重要。

第三，免费。硅基流动价格页把 `BAAI/bge-m3` 标为免费，输入输出都是 0 元每百万 token。付费版 `Pro/BAAI/bge-m3` 是 0.07 元每百万 token，可以作为免费版限流时的备选。52 个地点、165 条文档这个量级，免费额度绰绰有余。

第四，接口是 OpenAI 兼容格式。后面如果要换成智谱 embedding-3 或者别的服务，改一个 base URL 和模型名就行，业务代码不用动。这符合《迭代版》第 11.5 节的要求，业务代码不直接依赖某个供应商。

### 2.2 需要写入数据库的参数

`place_search_documents` 有 `embedding_model` 字段，用来防止不同向量混用。选定后写入以下值。

| 项目 | 值 |
| --- | --- |
| 模型标识 | `BAAI/bge-m3` |
| 向量维度 | 1024 |
| 单条输入上限 | 8192 token |
| 接口地址 | `https://api.siliconflow.cn/v1/embeddings` |

维度 1024 这个数字决定了 pgvector 列的定义，写错了要重建列并重新生成全部向量，所以在生成第一条向量之前必须先确认。确认方式是先用一条短文本调一次接口，数一下返回数组的长度。

### 2.3 有一个域名坑要避开

硅基流动的接口域名是 `.cn` 结尾，早期示例里出现过 `.com` 结尾的地址。两者不能混用。以接口文档当前指定的 `api.siliconflow.cn` 为准。

## 三　DeepSeek V4 Flash 的位置

它负责 C5 的问答生成，也就是拿到检索出来的段落之后写出回答。

选它做这件事是合适的。它支持 Tool Calls 和 Json Output，这两项是《迭代版》第 11.5 节要求验证的能力。上下文长度 1M，足够把多个地点的导览段落一起塞进去。价格上，空闲时段输入 1.5 元每百万 token、输出 4.5 元每百万 token，高峰时段翻倍，高峰时段是北京时间周一至周五 9:00 到 12:00 和 14:00 到 18:00。

有一件事要留意。V4 Flash 默认开启思考模式。导览问答这类任务不需要长思考，思考过程会产生额外的输出 token 并且拖慢响应。接入时应该关掉思考模式，或者把 `reasoning_effort` 调低，具体开关方式按官方的思考模式文档配置。

行程改动这类关键写入按《迭代版》第 11.5 节要用经过验证的稳定服务。V4 Flash 是否够稳，等 C6 的七项能力验证跑完再定。如果验证发现工具调用不够可靠，换成 `deepseek-v4-pro`，代码不用改，只改模型名。

## 四　需要大小姐提供的凭据

两个 key，都不要贴在聊天里，也不要写进仓库。

### 4.1 硅基流动 API Key

用途是生成向量。

取得方式是注册 `siliconflow.cn`，进控制台的 API 密钥管理，新建一个 key，格式是 `sk-` 开头。

### 4.2 DeepSeek API Key

用途是生成导览回答。

取得方式是在 DeepSeek 开放平台申请，格式同样是 `sk-` 开头。

### 4.3 填在哪里

本地开发填 `apps/worker/.dev.vars`，这个文件已经在 Git 忽略规则里。

```
SILICONFLOW_API_KEY=你的硅基流动key
DEEPSEEK_API_KEY=你的deepseek key
```

线上用 Cloudflare Secret，两条命令。

```bash
npx wrangler pages secret put SILICONFLOW_API_KEY --project-name china-stroll
npx wrangler pages secret put DEEPSEEK_API_KEY --project-name china-stroll
```

两个 key 都属于服务端密钥，不能放进任何 `VITE_` 变量，不能进浏览器，不能进日志。这条和 `SUPABASE_SERVICE_ROLE_KEY` 的处理方式一致。

## 五　拿到 key 之后的验证顺序

先验证再批量生成，顺序不能反。

第一步，用一条短文本调一次嵌入接口，确认返回向量长度是 1024。长度不对就停下来重新确认模型和参数。

第二步，准备一组真实提问，中文英文各若干条，覆盖开放时间、票务、历史、亲子四类问题。对每条提问算相似度，看召回的段落是否相关。判断标准是相关文档的余弦相似度明显高于无关文档，排序正确即可，不追求分差夸张。

第三步，向量列按 1024 维定义，批量生成 165 条文档的向量，把模型标识和维度一起写进记录。

第四步，跑 C6 的七项模型能力验证，产出验证记录归档到 references 目录。

前两步不通过就不进第三步。已经生成的向量如果换模型，必须全部重新生成，不能新旧混用。

## 六　置信度与局限

关于 DeepSeek 无嵌入接口这一条，置信度高。依据是官方文档模型与价格页的直接内容，且第三方文档 tabby 也明确写了 DeepSeek 当前不提供嵌入模型 API。

关于 bge-m3 免费这一条，置信度中等偏高。依据是硅基流动价格页当前标注，但免费政策可能变化，付费版单价 0.07 元每百万 token 作为兜底，成本依然可以忽略。

关于 bge-m3 的中英文检索质量，置信度中等。依据是公开基准成绩和第三方实测的相似度数据，还没有在本产品的真实景点内容上验证过。这就是第五节第二步必须做的原因。

关于 V4 Flash 能否支撑行程 Agent，暂无结论。必须等 C6 的七项验证跑完。
