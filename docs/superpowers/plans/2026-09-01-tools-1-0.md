# Tools 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Turn the Tools module into four working sections: navigation/rides, payment/exchange, translation/conversation, and service help — each with an honest offline/unavailable state and no fabricated provider output.

**Architecture:** Static reviewed guidance (payment, phrases, service contacts) ships in the client bundle. Exchange and translation sit behind provider-neutral Worker adapters; the exchange adapter returns an explicit unavailable state when no provider is configured, and translation reuses the SiliconFlow chat adapter. Navigation/ride links are generated locally from product coordinates and approved URL templates and never claim a booking was created.

**Tech Stack:** React 19, TypeScript, Hono, SiliconFlow chat adapter, Zod, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-01-mvp-function-completion-design.md`

## Global Constraints

- No fake exchange rate, translation, phone number, or booking state is displayed.
- External providers stay behind Worker adapters; the UI never talks to a provider directly.
- Translation never receives trip confirmation codes or private notes unless the user explicitly pastes that text.
- Static phrases and emergency/service guidance remain usable offline.
